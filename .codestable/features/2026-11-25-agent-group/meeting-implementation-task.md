# 任务：实现「开大会」（多 Agent 群聊讨论）

## 目标

在现有协作功能里实现「开大会」：几个 Agent 在一个群聊里对同一个议题各自提案、互评，每轮结束由作者决定下一步，最后生成正式计划，并在同一页接着进入快速模式。后端和界面一起做，先后端后界面。

## 范围

### 一、后端

1. **状态与恢复。** 会议、轮次、成员三层状态放进 `session-list.db`，用幂等迁移。重启后沿用 `RecoverInterruptedRuns` 和 `ContinueRun` 恢复。继续时只重新调度没交卷的成员，已落盘的跳过。
2. **第 1 轮并行提案。** 成员互相读不到对方草案靠提示词约束，不做暂存目录。后台读取各成员的工具调用记录，盲评期间读到别人草案的要标出。群组里关闭单聊的 `prependSwitchHint`。
3. **第 2 轮起轮流发言。** 后发言的成员读上一轮和本轮已落盘的文件。
4. **文件交接是铁律。** 每个草案、每轮互评、`03-共识与分歧.md`、`04-作者补充.md`、`04-补充答复/<成员>.md`、`作者裁决.md`、`05-正式计划.md` 都落成项目内文件，布局见 group-design.md 3.2。下一轮的模型只收到本阶段任务和文件路径，不依赖聊天记录。
5. **聊天不隐藏原文。** 只过滤 `mindfs-control` 控制块，模型原生文字完整保留。
6. **共识与分歧机械合并。** 后台按条目号（C1、D1）合并各成员原话，保留谁说的和出处，不让任何模型转述。同意必须写明检查了什么和剩余风险，只写“同意”算未确认，解析失败也算未确认。
7. **出处核验。** 沿用快速模式已有的文件行号检查，结果写进成员消息的脚注。
8. **@ 点名。** 作者 `@成员` 时该成员当场回答，答复另存文件；不 `@` 的发言记入 `04-作者补充.md` 带入下一轮。成员之间的 `@` 只是称呼，不触发调度。邮箱和 `@Override` 这类按普通文本。
9. **一轮一停，到上限转人工裁决。** 每轮结束停下，由作者开下一轮。轮次上限放在群组模板里，默认 3。到上限仍有未对齐的条目时，必须由作者逐条裁决（采纳某成员方案 / 自己写说明 / 暂不决定）才能生成正式计划，裁决写入 `作者裁决.md`。连续两轮同一成员立场没变且没有新出处的条目标为“僵持”，第 2 轮结束就提示可裁决。
10. **正式计划衔接快速模式。** 确认后，正式计划正文写入快速模式运行的 `00-任务说明.md`，并保留指向会议 `05-正式计划.md` 的出处。快速模式仍是自己的运行和目录，不改它已有的后台逻辑。发给主模型的只有一句短指令加路径。
11. **只读保障。** 成员全程只读，沿用现有三协议只读门禁和审核后的工作区事后检查。

### 二、界面

按 ui-design.md 5.0 到 5.6 实现，对照原型：

- 全员共用的群聊流：作者议题、各成员原文、作者插话、`@` 点名答复在同一条时间线。轮次之间有分隔条。
- 顶部只留状态行、成员头像、议题一行和流程位置条（提案、互评、对齐、计划、实现）。
- 每条消息只有一行安静的脚注：立场、出处核验、草案或互评文件、过程。长消息折叠到 5 行并带“展开全文”，文字完整保留。
- 已结束的轮次折叠成一行，只有当前轮展开。
- 共识与分歧按条目显示，可展开看各成员原话，能跳到该成员的完整对话和互评文件。
- 输入框在群里，支持 `@` 点名和附件。
- 到轮次上限转人工裁决：主按钮是「裁决」，并排显示各方说法，全部选完才能生成正式计划。原型没有演示这一步，按 group-design.md 3.3 和 ui-design.md 5.2 实现。
- 确认并开始实现后，会议折叠成一行，快速模式的五步卡片在同一页接着出现，不再弹新对话框。
- 复用现有组件：`SessionViewer`、`SessionActivity`、`ActionBar`、`AgentSelector`、`FileViewer`，不重造。
- 极简风格，少边框少标签，颜色只表示状态。浅色、深色和手机宽度都要核对。
