# 多模型协作（快速模式 + 群组讨论 + 全局模板）：界面与交互设计

本设计文档配套交互式 HTML 原型：[ui-prototype.html](ui-prototype.html)（可直接用浏览器打开，支持切换桌面端 / IDEA 侧栏 / 手机端、亮暗主题；IDEA 窗口可拖左边缘改宽度，分隔条可拖，会话列表和对话细节可收起，可实际点击体验全部核心交互）。

> **2026-11-25 架构与界面方向敲定**：
> 1. **页面外壳独立，单聊代码零侵入**：多模型协作（快速模式 + 群组讨论）使用单独的完整协作界面（`运行列表 | 卡片区 | 对话细节`），不硬塞进“单聊列表 + 单栏聊天 + 右侧 Git 栏”的旧框架，普通单聊代码一行不动；两者之间只保留 **3 个最小接触点**（进入入口、`待你处理 N` 角标、`← 返回单聊` 出口）。
> 2. **内部零件严禁重造，能重用的全部重用**：右栏对话直接原样挂载现有 **`SessionViewer` + `ToolActivity` + `AskUser` + `SessionActivity`（双行活动块）+ `ActionBar`（含 `AgentSelector` 与原生 `PermissionSelector`）**；成员配置直接复用 `AgentSelector` 双栏菜单；Diff 与交付文档预览直接复用 `GitDiffViewer` / `FileViewer`；五套外观变量与状态呼吸语义全部沿用现有实现。
> 3. **三端与动态布局**：左边运行列表可收起可拖宽，中间卡片区自动滚动跟随当前运行步并带呼吸灯，右边对话细节可拖宽可收起；手机与窄 IDEA 窗口自动切换为两层（外层卡片 → 点进全屏对话）。详见 2.1、2.5、2.7、第 6 节与第 9 节。

实现前先通过本设计文档和 HTML 原型对齐交互，再按 [quick-mode-design.md](quick-mode-design.md) 的 Q0 → Q1 → Q2 → Q3 顺序落地。

## 1. 设计原则

1. **CLI 原生优先，绝不造展示名**
   - 所有 Agent、模型、思考强度、权限模式一律显示 CLI 原生标识，例如 `codex / gpt-5.4 · high`、`claude / claude-opus-4-6 · max`、`bypassPermissions`、`full-access`。
   - 成员列表中 Agent 自带原生模型始终在前、中转站模型去重后在后。
2. **默认模板一步开干，零重复配置**
   - 快速模式和群组讨论各自支持一个全局默认模板；进入页面直接输入任务即可运行，不需要每次重选成员。
   - 临时修改成员仅对本次生效，顶部轻量提示“相对模板已调整”，支持一键“保存为新模板”或“覆盖原模板”。
3. **不盲从、不遮掩、作者始终做最终拍板**
   - 后台出处校验结果（`✓ 源码已核对` / `⚠ 查无此处`）、主模型回应完整性、解析失败兜底、工作区只读事后核对、测试真实结果（`通过` / `失败` / `跳过`）全部如实暴露，不自动隐藏，不默认“同意”或“通过”。
   - 模板成员不可用时明确标红阻断启动，由作者自选替代模型，绝不静默替换。
4. **极简克制（类 Apple 风格）：外层只看脉络与拍板，细节与指令全部归入右侧对话（2026-11-25 作者强调）**
   - **严禁往卡片上堆砌徽章、说明横幅与次级工具按钮**：不放重复的顶部 7 步条（纵向卡片本身就是进度），不放教学横幅，不用五颜六色的胶囊刷屏。
   - **画布与卡片层次分明**：卡片区采用浅灰分组底色（如 `#F5F5F7` / 深色 `#0C0E12`），卡片采用纯白/深灰实底 + 清晰 `1px` 实线边框（`#D2D2D7` / `#2A2F3A`）与留白；选中态（`2px` 蓝框）、运行态（柔和蓝呼吸框）、待拍板态（琥珀色实框）、未开始态（静默浅卡）四种边界一眼区分。
   - **每张卡片最多三层信息**：① 标题 + 原生模型标识 + 状态；② 一两句人话结论摘要；③ 极安静的交付文件名或改动数字。审核逐条明细、完整 Diff、文档正文、让模型删过程文件或补充自定义指示，**全部点进右侧复用的对话视图里看和说**，不在外层卡片重复造控件。
5. **总览与执行过程并存，零件不重造（2026-11-25 敲定）**
   - 左边是极简阶段 / 成员卡片；右边是选中卡片对应的完整对话，**100% 原样复用现有 `SessionViewer` + `ToolActivity` + `AskUser` + `SessionActivity` + `ActionBar`（含 `AgentSelector` 与原生 `PermissionSelector`）**。
   - 发现跑偏、想补充复杂指示、或结束后想让模型做额外清理，直接在右边 `ActionBar` 对话框里打断或发消息解决。

## 2.5 页面骨架：运行列表 | 卡片区 | 对话细节（独立协作外壳）

从左到右三块，宽度都由用户掌控（无第 4 栏 Git 侧栏，代码变更直接在卡片内点开复用的 `GitDiffViewer` 查看）：

1. **运行列表（复用 `SessionList` / `SessionCard` 零件，只放多模型运行，可收起）**
   - 顶部固定 `← 返回单聊` 出口 + 当前项目名 + 新建入口（仅 `⚡ 新建快速`、`👥 新建群组`，不含普通单聊）。
   - 支持按状态筛选（`全部` / `等你处理` / `运行中`）。
   - 桌面：可收起成 44px 窄条（保留返回单聊、新建入口和各运行的呼吸灯 / 待处理蓝点），展开时可拖宽 180–380px。
   - IDEA：沿用工具栏「运行列表」图标开合，默认收起。
   - 手机和窄窗口：从左边滑出的抽屉，点遮罩收起。
2. **卡片区**
   - 快速模式：每个阶段一张卡（主模型实现、只读审核、逐条回应、分歧裁决、修改与测试）。群组：每个成员一张卡，按轮次切换。
   - 卡片只放“结论层”信息：状态与紧凑版 `SessionActivity` 活动行、出处校验、改动摘要、测试结果、交付文档芯片，以及分歧裁决面板。
   - 点卡片任意空白处或底部的「查看对话 ›」即选中；选中的卡片有蓝色描边，右边随之切换。
   - 分歧裁决的左右并排是按**卡片区自身宽度**决定的：够宽并排，不够宽自动上下叠放，不看设备类型。
3. **对话细节（100% 原样复用单聊组件栈）**
   - 头部：阶段 / 成员名、原生 Agent·模型·权限、状态；右上角可收起成 38px 窄条（收起后卡片区占满）。
   - 中间：原样挂载 **`SessionViewer`**（完整消息流、Thinking 折叠块、`ToolActivity` 工具调用卡片、`edit_file` 行内 Diff、`AskUser` 授权/提问卡片）。
   - 底部状态：原样挂载 **`SessionActivity`**（`ActivityEmoji` 表情 + 当前活动文案 + 第二行 `已用时`）。
   - 底部输入：原样挂载 **`ActionBar`**（含 `AgentSelector` 模型/思考强度胶囊、原生 `PermissionSelector` 权限胶囊、附件按钮、IDEA `添加当前文件`、运行中红色停止/打断按钮与发送按钮）。在阶段/成员对话里发送即对该模型纠偏插话；群组要广播给全员则用卡片区底部的全员 `ActionBar`。

**宽度调整**：会话列表与卡片之间、卡片与对话细节之间各有一条分隔条，可鼠标拖、键盘 ←/→ 微调（每次 16px）、双击还原；卡片区最窄 280px、对话细节最窄 300px。宽度记在本机浏览器里，存储不可用时只是不记住。

**两层模式（手机，以及窄到放不下两栏的窗口）**：当卡片加对话的可用宽度不足约 600px，自动改为两层——

- 第一层：卡片列表（含分歧裁决）。
- 点任意卡片进入第二层：全屏对话细节，左上角 `‹ 卡片` 返回，返回时回到刚才的滚动位置。干预条固定在对话页底部。
- 手机始终是两层；IDEA 窗口拖窄到阈值以下也自动变成两层，拖宽又恢复两栏。

**群组盲评的隔离边界**：作者可以点任意成员卡片旁听并干预；但**成员 A 的对话与中间输出绝对不会注入给成员 B**，盲评隔离由后端上下文严格保证。

## 2.7 运行中的自动跟随与呼吸灯（2026-11-25 作者要求）

**自动跟随当前步骤**：一共 7 步、执行到第 6 步时，卡片区不能要求用户自己往下翻。

- 默认处于“跟随”状态：每当步骤推进，卡片区自动平滑滚动到当前步骤的卡片（卡片顶部对齐，不是滚到底），右边的对话细节同时切到该步骤的对话。轮到用户裁决时同样滚到分歧裁决卡，并弹一条轻提示“轮到你了”。
- **不和用户抢**：用户在卡片区手动滚动，或点开另一张卡片去看，立即退出跟随，页面不再自动动。此时底部出现一个浮动胶囊“● 第 N 步执行中 · 回到当前 ↓”，点一下恢复跟随并回到当前步骤。这和现有 `SessionViewer` 里“手动上滚后出现回到底部”的做法一致。
- 顶部 7 步阶段条每一步可点击，直接定位到对应卡片（定位后同样退出跟随）。
- 手机上卡片页和对话页是两层：跟随只在卡片页滚动；用户停在某一步的对话页时，对话内容随步骤推进自动切换。
- 阶段更新到达后立即更新卡片。当前卡片的「检查进度并继续」按钮按后台已保存的阶段定位，有运行中的回合就显示当前进度，中断时从当前未完成步骤恢复，分歧裁决保留作者提交入口。

**呼吸灯与状态语言**：沿用现有活动块的状态含义，不另造一套。

| 状态 | 卡片表现 | 对应现有语言 |
| --- | --- | --- |
| 执行中 | 网页卡片边框沿用单聊流光配置，运行列表圆点按同一开关、颜色和速度明暗呼吸。关闭时仍显示进行中标记。 | 现有 `SessionActivity` 的 work：表情（✏️ 编辑、👀 读取、🤔 思考、⚡ 运行）+ 文字 + 用时 |
| 等你处理 | 琥珀色静态高亮，不呼吸 | 现有 wait（💬），等用户时不亮流光 |
| 已完成 | 普通卡片，表情 👍 | 现有 done |
| 出错 | 红色静态，😱 | 现有 error |
| 未开始 | 变淡，只显示标题与“等待上一步” | — |

- 只有“真的在干活”才呼吸；等你、已结束、出错都不呼吸，避免用户误以为还在跑。
- 同一状态也出现在：顶部阶段条当前步骤、会话列表里这条会话的圆点（执行中呼吸，等你为静态蓝点）。
- 尊重系统“减少动态效果”设置：开启时去掉呼吸动画，只保留静态描边（现有表情组件已这样处理）。
- 群组同理：每个成员卡片各有自己的状态，盲评时三位成员可能同时呼吸。

## 2.6 阶段交付文档（存项目内）与结束清理

- **阶段间只认交付文档，不认口头“写好了”**：
  - 每一张阶段卡片的头部/底部均显式展示本阶段产出的**项目内交付文档芯片**（位于 `.mindfs/runs/<run-id>/`）：
    - 阶段 1：`01-impl.md`（实现与变更说明）
    - 阶段 2：`02-review.md`（只读审核文档，由后台代写，排除在只读/Diff 误报之外）
    - 阶段 3：`03-response.md`（主模型逐条回应文档）
    - 阶段 4：`04-decisions.md`（作者分歧裁决记录）
    - 阶段 5/6：`05-report.md`（最终修改与测试/构建报告）
  - 点击任意交付文档芯片即可直接弹窗/抽屉预览完整 Markdown 内容；若作者在某阶段中途做了人工干预，干预完成后该阶段更新对应的交付文档，下一阶段直接按这份最新文档继续，整体流程完全解耦不受影响。
- **任务结束后的文档清理**：
  - 流程结束后，在最终完成卡片中展示本次在项目内生成的过程文档列表（`.mindfs/runs/<run-id>/`），提供：
    - **`🗑 删除全部过程文档`**（默认推荐，直接清除无后续意义的临时交付文档，保持项目目录和 Git 干净）；
    - **按文件勾选保留**（例如群组讨论结束后只想留下 `final-conclusion.md`，其余 `round1/round2` 过程文档一键删掉）。

## 2. 总体入口与信息架构（独立外壳 + 3 个最小接触点）

### 2.1 与普通单聊的关系

多模型协作拥有独立的完整界面，普通单聊界面不混入阶段子会话、不改三栏布局。两者仅通过 3 个轻量接触点衔接：

1. **进入入口**：普通单聊工作台顶部「新建」旁增加 `⚡ 多模型协作` 入口按钮，点击切换到独立的多模型协作界面。
2. **待你处理角标**：当协作运行处于“等你裁决分歧”“等你确认最终结论”或阶段内出现 `AskUser` 授权提问时，入口按钮与运行列表同步显示 `● N 待处理` 计数角标。
3. **返回出口**：协作界面左上角（桌面左栏顶部、IDEA 工具栏、手机顶栏）固定提供 `← 返回单聊`，一键回到原单聊会话，状态互不干扰。

### 2.2 左侧运行列表（仅承载快速模式与群组讨论）

- 新建区仅提供 **`⚡ 新建快速`** 与 **`👥 新建群组`**，以及底部的 **`🧩 全局模板`** 入口。
- 列表项复用现有 `SessionCard` 样式，带模式标签（`快速` / `群组`）、当前步骤或轮次摘要，以及状态圆点（执行中蓝色呼吸，等你处理静态蓝/琥珀点）。

## 3. 全局模板交互（快速模式 & 群组共用）

对应 [quick-mode-design.md](quick-mode-design.md) 4.7 与 [group-design.md](group-design.md) 第 6 节。

### 3.1 发起页顶部模板配置条

- **默认态**：自动应用当前模式的全局默认模板，顶部以单行/双行紧凑胶囊显示：
  - 模板选择器下拉框（例如：`[默认] Codex 主写 + Claude 严审 ▾`）+ `管理模板` 按钮。
  - 成员槽位胶囊（点击任意胶囊可直接弹出原生 Agent / 模型 / 思考强度选择器进行临时修改）：
    - 快速模式：`主模型: codex / gpt-5.4 · high` + `审核模型: claude / claude-opus-4-6 · high (只读)`
    - 群组模式：多个槽位胶囊 + `最终文档作者` 选择器 + `轮次上限 (3/5)`
- **临时修改态（未保存回模板）**：
  - 任一成员被临时调整后，模板条下方滑出浅蓝色轻提示栏：
    `本次配置已相对模板「Codex 主写 + Claude 严审」修改（仅对本次生效）` + `[覆盖原模板]` `[保存为新模板]` `[还原]`。
  - 点击“覆盖原模板”直接更新该全局模板；点击“保存为新模板”展开内联命名框回车即保存。
- **不可用成员告警态**：
  - 应用模板时后台逐个检查每个槽位的 Agent 是否已安装、模型是否仍在可用列表中。
  - 若某成员不可用，对应槽位显示红色边框与明确原因标签（如 `模型已下线：claude / claude-3-5-sonnet-old` 或 `Agent 未安装：gemini`），主输入区发送按钮置灰并提示“请先为不可用成员选择替代模型”，点击该槽位即可直接重选，绝不静默替换。
- **同厂家提醒（仅群组模式）**：
  - 若群组所有成员均来自同一厂家，展示柔和的灰/琥珀色提示条：“当前成员均为同一厂家，建议混用不同厂家模型以降低趋同偏见”（仅提示，不阻止发起）。

### 3.2 全局模板管理视图

- 弹窗/抽屉展示用户级全局模板（跨所有项目共用），顶部提供两个过滤 Tab：`快速模式模板` / `群组讨论模板`。
- 每张模板卡片展示：模板名称、`默认` 徽标、全部成员的原生 `agent / model · effort` 与角色、群组专属参数（最终文档作者、轮次上限）、以及操作按钮：`设为默认`、`应用到当前`、`编辑`、`删除`。
- 明确提示：**“应用模板是复制快照，修改或删除模板不会影响任何历史运行记录。”**

## 4. 快速模式交互流程（一写一审一轮，一期优先）

对应 [quick-mode-design.md](quick-mode-design.md) 第 2 节与第 4 节。

### 4.1 顶部固定 7 步阶段条

始终固定在主内容区顶部，横向展示完整生命周期，强调“严格一轮、不自动循环”：

```text
[1 主模型实现] → [2 只读审核] → [3 逐条回应] → [4 分歧裁决] → [5 按决定修改] → [6 测试与构建] → [7 完成]
```

- 已完成步骤：绿色勾选（点击可快速滚动定位到对应阶段卡片）。
- 当前执行步骤：蓝色脉冲高亮。
- 无需执行的步骤（例如主模型全部认同审核意见、无分歧时）：`4 分歧裁决` 自动标记为 `无分歧·已跳过`，直接进入第 5/6 步。
- 异常提醒（仅在触发时出现）：
  - 只读兜底告警：若审核 Agent 无原生只读模式且事后工作区对比发现文件变化，顶部常驻橙红色告警条并附“查看工作区变化”入口。
  - `turndiff` 未观察到改动时：明确显示“本轮未观察到工作区改动（可能未写入文件或超出观察范围），请核实”，不静默当成“无改动”。

### 4.2 阶段 1：主模型实现

- 主模型在对话流中正常流式输出思路与工具调用（完全复用现有 `SessionViewer` / `ToolActivity`）。
- 实现完成后附一张紧凑的 **本轮改动摘要卡片**（基于 `turndiff`）：列出变更文件与增删行数，并附固定说明：“以上为该轮期间工作区全部变化，可能包含你手动编辑的无关改动”。

### 4.3 阶段 2：审核模型只读审核

- 审核模型卡片头部清晰标明：`审核模型 · claude / claude-opus-4-6 · high` + `只读模式` 徽标（或 `事后快照核对` 徽标）。
- 隐藏的机器控制块由后台过滤器实时剥离，作者只看到干净的自然语言说明 + 自动解析出的 **结构化审核文档卡片**（右上角标注保存路径位于会话元数据目录，不写入源码、不污染 Git）。
- 每条审核意见卡片包含：
  - 编号（`#1`、`#2`…）
  - 维度徽标：`功能`（蓝）或 `规范`（紫）
  - 严重程度：`高`（红）/ `中`（橙）/ `低`（灰）
  - 文件与行号（可点击跳转查看）+ **后台出处校验徽标**：
    - `✓ 源码已核对`（绿色）
    - `⚠ 查无此处`（橙红色高亮，提示文件或行号在当前工作区不存在）
  - 规范引用（仅规范类意见强制显示）：明确列出引用自 `AGENTS.md` 哪一节或具体 skill 名称。
  - 问题描述与修改建议。

### 4.4 阶段 3：主模型逐条回应

- 展示机械完整性校验汇总条：`审核共 4 条 · 主模型已逐条回应 4/4 条（认同并已改 2 条 · 有疑问待裁决 2 条）`。
- 若后台检测到缺漏条目，明确提示“回应缺少 #3，已阻断进入下一步，请重试”，绝不当作默认认同。
- 若某条回应格式解析失败，自动归类到“有疑问待裁决”并标注 `解析失败·保守交由作者裁决`。
- **已认同并修改的条目**默认折叠为一个清爽列表（展示条号、简述、主模型写明的“改了哪里” + `查看真实 Diff` 按钮，防止主模型口头敷衍）。

### 4.5 阶段 4：作者分歧裁决面板（核心交互）

当存在任意“有疑问 / 不认同 / 解析失败”条目时，流程暂停在此阶段，在主界面呈现 **分歧裁决面板**：

- 每条分歧独立成卡，卡头展示条号、维度、严重程度、出处校验徽标。
- **双栏并排对照**（桌面端左右 50/50 并排；IDEA 侧栏与手机端自动折为上下双卡片）：
  - **左栏｜审核模型意见**：原生模型标识、规范引用依据、具体指出什么问题、建议怎么改。
  - **右栏｜主模型回应**：原生模型标识、状态标签（`不认同` / `拿不准` / `格式解析失败`）、主模型给出的技术理由与代码依据。
- **逐条裁决操作区**（三选一，默认均未选中，禁止替作者预选）：
  - `按审核改`
  - `不改（保留主模型）`
  - `其他指示`（选中后在下方展开文本输入框，填写自定义要求）
- **底部吸底确认栏**：
  - 左侧显示进度：`已裁决 1 / 2 条`（未裁决完时列出还差哪几条）。
  - 右侧主按钮：`提交裁决，交由主模型处理`（全部条数均做出选择、且选“其他指示”的已填内容后才可点击）。

### 4.6 阶段 5 & 6：按决定修改 + 项目测试与构建兜底

- 展示主模型按作者裁决完成后的最终修改摘要与 **真实 Diff 视图**。
- 展示 **项目测试 / 构建结果卡片**（来自 `AGENTS.md` 与任务要求）：
  - 每条命令独立一行，状态严格区分三态：
    - `通过`（绿）
    - `失败`（红，自动展开失败日志摘要 + 完整输出折叠区）
    - `跳过`（灰/黄，附跳过原因，**绝不显示为通过**）
  - **失败时不自动返工**：明确告知“测试存在失败，快速模式遵循严格一轮，不自动重新修改”，由作者决定是直接追问还是另开一轮。

## 5. 完整群组讨论交互流程（二期）

对应 [group-design.md](group-design.md) 第 2、3、5 节。

### 5.1 顶部讨论状态条

- 左侧：当前阶段与轮次，例如 `第 1/3 轮 · 盲评隔离中` / `第 2/3 轮 · 互评辩论` / `最终结论核对中`（硬上限 5 轮）。
- 中间：各成员状态胶囊（原生 `agent / model`，区分同厂家多槽位，例如 `#1 claude/opus-4-6`、`#2 claude/sonnet-4-6`、`#3 codex/gpt-5.4`），标注状态图标（`阅读中` / `已交 v1` / `已表态` / `未确认`）。
- 右侧：随时可用的 **`暂停并插话`** 按钮与 **`结束并生成结论`** 按钮。
  - 点击“暂停并插话”立即暂停后续自动轮转，输入框高亮为“全员广播插话（高优先级）”，发送后同时送达所有成员。

### 5.2 第 1 轮：盲评视图

- 顶部显示清晰的隔离说明条：`盲评进行中：各成员仅看到任务与代码库，彼此输出完全不可见`。
- 主区采用 **成员文档切换标签 / 并排卡片**：
  - 每个成员一份独立文档卡（标明 `v1`），带后台出处校验统计（如 `✓ 5/5 处源码已核对` 或 `⚠ 1 处查无此处`）。
  - 卡片底部收起“隐藏控制块已解析：初始立场摘要”。

### 5.3 第 2..N 轮：互评与立场追溯视图

- 按时间线流式展示各成员的互评发言，每条消息清晰显示原生发言人槽位与模型标识。
- **反盲从表态徽标（强制结构化展示）**：
  - `同意`：必须附带两项折叠/内联内容——**“已检查内容”**与**“剩余风险”**。
  - `反对`：高亮列出具体异议点与源码行号依据（带出处校验徽标）。
  - `无效表态 / 未确认`：当模型只写“我同意”未附检查与风险，或控制块解析失败时，以黄色警告标签标出“未计入有效同意，按未确认处理”。
- **立场变更可追溯**：若某成员在互评后改变方案，系统强制生成 **`v2` 新版文档**，并在消息卡片中显式呈现“立场变化：`v1 → v2`”及变更原因，支持点击对比 `v1` 与 `v2` 差异。

### 5.4 `@点名` 交互

- 在群组输入框键入 `@` 时，向上弹出成员候选浮层：
  - 显示每个槽位的唯一名称与原生模型（例如 `@codex-1 (codex / gpt-5.4)`、`@claude-1 (claude / claude-opus-4-6)`、`@claude-2 (claude / claude-sonnet-4-6)`），解决同厂家多槽位歧义。
  - 粘贴代码或输入 Java 注解（如 `@Override`、`@Transactional`）以及邮箱地址时，后端与前端按 `tarobird` 边界规则识别为普通文本，不拦截发送。

### 5.5 最终结论文档与成员核对视图

- 由发起时指定的“最终文档作者”产出，固定 5 个清晰区块：
  1. **结论方案**
  2. **共识点**
  3. **未解决的分歧**（固定保留，不抹平；逐条列明谁坚持什么、依据是什么）
  4. **采纳依据来源**（标明引用了哪些成员的哪版文档与源码出处）
  5. **成员核对状态条**（每个非作者成员逐一确认“我的观点是否被准确表达”：`✓ 已确认` / `⚠ 有异议（附说明）` / `○ 未确认`）
- 底部作者拍板区：`确认定稿` / `插话补充` / `指定主刀进入实现`。

## 9. 独立界面外壳与现有零件复用清单（2026-11-25 已确定方向）

### 9.1 为什么采用“独立页面外壳 + 内部零件全复用”

- **外壳独立**：普通单聊是“一人一 Agent 一条时间线”，快速模式与群组是“一次多阶段/多成员任务 + 人工裁决节点”。独立外壳让普通单聊代码零改动、零回归风险，也消除了第 4 栏 Git 侧栏挤压宽度的问题。
- **零件严禁重造**：新界面只负责组织“运行列表 | 卡片区 | 对话细节”的外壳编排和阶段卡片，所有涉及到会话展示、工具活动、模型与权限选择、输入发送、文件/Diff 查看的零件一律直接复用现有组件：

| 协作界面区域 | 直接复用的现有组件 / 服务 | 作用说明 |
| --- | --- | --- |
| 右栏对话流 | `components/SessionViewer.tsx` + `ToolActivity` + `AskUser` | 原样渲染思考过程、工具调用、行内 Diff、终端输出与原生授权/提问卡 |
| 右栏底部状态与卡片状态行 | `SessionActivity` + `ActivityEmoji`（`.session-activity`） | 原样展示表情、当前动作文案、已用时与呼吸状态语义 |
| 右栏纠偏输入 & 发起任务输入 & 群组广播输入 | `components/ActionBar.tsx` | 原样复用输入框、附件、IDEA `添加当前文件`、`@` 点名、停止/打断与发送 |
| 槽位选模 & 对话栏模型切换 | `components/AgentSelector.tsx` + `services/agentDefaults.ts` | 原样复用左 Agent、右模型（原生在前·中转在后）/ 思考强度 / 模式双栏菜单 |
| 权限模式选择 | `components/PermissionSelector.tsx` + `services/nativePermissions.ts` | 原样展示 CLI 原生权限标识（`full-access`、`bypassPermissions`、`read-only` 等） |
| 交付文档预览 & 真实改动查看 | `components/FileViewer.tsx` + `components/GitDiffViewer.tsx` | 原样查看 `.mindfs/runs/<run-id>/*.md` 与 `turndiff` 代码差异 |
| 左栏运行条目 & 搜索筛选 | `components/SessionCard.tsx` + 搜索/筛选头 | 沿用现有卡片布局、置顶/删除菜单与待处理圆点 |
| 三端壳与主题 | `IdeaWorkbench.tsx` 工具栏图标、手机抽屉/安全区变量、全局 5 套外观 CSS 变量 | 视觉与操作手感和现有单聊完全一致 |

### 9.2 实现前在 Q0 核实的 3 件事

1. **后端阶段会话隔离**：阶段 / 成员背后的真实 CLI 会话如何在后端创建并归属到运行记录下，同时**不混入普通单聊的 `/api/sessions` 列表**（需读 `session` / `usecase` 代码确认，不提前假设）。
2. **多路活动订阅开销**：卡片活动行订阅各阶段会话状态，尤其群组盲评 3 个成员同时运行时的事件推送与渲染开销。
3. **窄右栏适配验证**：现有 `SessionViewer` + `SessionActivity` + `ActionBar` 在右栏最小宽度（约 300px）下的真实 DOM 表现，确保按钮不溢出、不截断。
