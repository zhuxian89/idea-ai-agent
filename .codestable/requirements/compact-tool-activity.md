# 简洁的工具活动

## 用户故事

- 阅读 Codex 或 Claude 的工作过程时，我希望先看到简短活动，进展和结果文字保持醒目。
- 一段连续操作完成后，我希望它们收成简短分组，需要时再逐项查看；正在阅读的详情和待处理操作保持可见。
- 查看工具活动和底部运行提示时，我能看到一致、可辨认的操作摘要；切换中英文仍能理解同一条记录。
- 切换会话、刷新或重新导入原生历史后，我仍能看到相同的可用信息，不会多出重复工具；已有缓存和草稿保留。
- 需要核对命令和结果时，我可以主动展开工具详情；切换会话再回来，应用记得我打开或关闭的条目。
- 日志继续更新时，我向上阅读的位置不被拉走；需要时可回到最新，或复制完整命令/输出。
- 详情加载失败时，已有内容仍可查看，临时失败可以重试。
- 等待执行时，我仍能看到累计等待时间和距离上次更新的时间。
- 查看执行结果时，我能区分成功、失败、拒绝、取消、中断及结果未知；工具提供了原生耗时才显示该耗时。

## 为什么需要

完整命令作为高亮卡片标题会占据注意力，连续操作尤其难读。已经收起日志仍不足以让阅读变轻松。

## 怎么解决

普通工具默认显示轻量摘要行，点击后查看已有详情。同一 Agent、同一轮次的连续完成普通操作达到 3 项且所在段落闭合时收成组；组只显示命令或操作数量，展开后按原顺序查看子项。两种 Agent 使用相同交互，活动行与底部使用同一套操作摘要，例如“读取 README.md”“在 src 中搜索 activity”；复杂脚本保守显示，已有描述保持原文。应用内按会话记住显式展开选择，运行中的已开日志自动更新，完成后核对最终详情。特殊操作和运行计时继续保留。实时与历史工具的原生结果和可用耗时随记录保存，缺少工具结果时不因整轮结束而显示成功；原始命令与输出仍可查看。

## 边界

本能力覆盖单项活动与连续完成段分组，不自动生成任务说明，也不改输入框或特殊操作的内部界面。正文始终独立；文件修改、任务、用户 shell、异常和待交互单列。缺少可靠调用、Agent 或轮次身份时不聚合，运行中的开放尾段保留逐项展示。耗时取自单次工具结果，0 有效，缺失/非法值省略；它不替代底部两项会话计时。摘要仅使用已有信息，不猜测脚本含义或业务成功；缺失信息时保守降级，有原生日志且归属明确的旧工具在恢复/同步时补录；没有原始数据或无法可靠匹配时保持旧内容，不猜测缺失信息。正在运行的会话暂缓历史补录。展开记忆只在应用内存保留，最多 50 个会话、每会话合计 500 个条目/组选择，刷新/重启恢复默认；完整日志不进入全局缓存，详情请求与复制不改变会话计时。
