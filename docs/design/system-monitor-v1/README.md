## 已确认的决定（2026-11-20）

- **位置：左侧栏左下角**，放在现有蓝色“手机扫码连接”按钮的上方，按钮和下面的灰字不动。
- **手机上不展示。**
- **阈值：** 低于 70% 正常，70% 到 89% 偏高，90% 及以上过载。

## 设计内容

**收起时**是一张和侧栏等宽的小卡片，两个圆环加数字：`CPU 41%｜内存 67%`。圆环里各有一个图标：芯片是 CPU，内存条是内存，所以即使看不清文字也能分清。数字等宽，避免跳动。点击卡片或按回车展开详情，点别处或按 Esc 收起。

**展开时**在卡片上方弹出详情：标题是“这台电脑”加后台所在电脑的名字，右侧小圆点表示每 2 秒更新。下面两块，各有大圆环（中间是百分比）、说明和最近 60 秒的面积走势：处理器显示核数；内存显示已用 / 总量和可用。底部一句说明：显示的是运行 Local AI Agent 的电脑，不是你正在看的手机或浏览器所在的设备，因为通过公网访问时最容易混淆。

**颜色：** 正常用主题强调色，偏高为琥珀色，过载为红色。数字、圆环和图标一起变色，数字始终显示，不靠颜色单独传达。偏高时详情顶部多一条“负载偏高”，过载时提示“负载很高，Agent 响应可能变慢”。

**状态**

- 读取中：圆环显示旋转的小弧，数字为 `--`，不能展开。
- 读取失败：整张卡片不显示，侧栏底部和现在一样。旧版后台没有这个接口、公网中转暂时不通时都这样处理，不弹错误。
- 侧栏收起时随侧栏一起隐藏。
- 减少动态效果：圆环过渡、旋转和更新圆点的闪动全部关闭。

**主题：** 只使用主题 token（`--accent`、`--amber`、`--danger`、`--line-strong`、`--surface` 等）。过载红色和偏高琥珀在深色下用更亮的值，与 v2 的状态色一致。

## 实现后的调整（2026-11-20）

在真实页面里实现并对照后，设计稿同步了以下几处：

- 弹窗宽度与侧栏一致（约 236px），原来的 300px 会被侧栏裁掉右半边。电脑名字挪到标题下方一行，“每 2 秒更新”留在标题右侧；大圆环从 64px 改为 56px。
- 弹窗背景必须不透明：苔痕绿影、翠谷金光的面板色带透明度，会透出后面的文字。
- 走势按真实时间摆放点，收起时 5 秒一个点也不会被拉伸成一整分钟；刚展开时只有右侧几个点，一分钟后铺满。
- 页面刚打开时受保护的接口还没就绪，这不算读取失败，1 秒后重试；真正失败（旧版后台、公网不通）才隐藏整张卡片并改为 30 秒重试。

## 页脚对齐调整（2026-11-20，设计稿待确认）

实现后用户反馈“整体凌乱、对不齐”。在隔离实例里量了页脚各元素，再对照真实截图，问题是：

- 状态卡与按钮外框同宽，但长相不同：高度 46 对 36，圆角 12 对 10，状态卡是实心底加 1px 外圈，按钮是线框；按钮文字居中、灰色，整行显得空。
- 状态卡里 CPU、内存各自居中，“内存”（英文 Memory）比“CPU”长，两半内容宽度不一，分隔线偏离中线；英文下内容挤，分隔线会贴到圆环上。
- 下面的文字四种对齐并存：版本靠左、“检查更新”靠右且字号偏大（14 对 12）、状态靠左、安装提示居中且字号只有 11。

打开 [footer-alignment.html](footer-alignment.html) 左右对比，勾选“显示对齐线”看对齐轴；截图：[深色](footer-dark.png)、[深色带对齐线](footer-dark-guides.png)、[浅色](footer-light.png)、[苔痕绿影偏高](footer-warn-moss.png)。

调整内容：

- 状态卡和按钮同宽、同圆角（10px），**底色与侧栏一致，不填充**，只用 1px 线条（用户反馈第一版填充色“太深、不好看”）。
- “手机扫码连接”按钮的**文字颜色和边框保持现状**（用户要求不改），只在左边加二维码图标、右边加箭头，内容靠左，高 40px；图标与状态卡里圆环的左缘、下方文字在同一条线上。按钮名称不改：本机页面仍是“从公网访问”，公网页面仍是“手机扫码连接”。
- 状态卡内 CPU 与内存各占一半，名称在上、数字在下，列对齐，宽度不再取决于名称长短。
- 下方文字统一靠左，缩进 10px，与状态卡里圆环的左缘在同一条线上；“检查更新”右对齐，字号统一 12px；状态加一个绿点；安装提示也靠左；版本只写“0.1.52”，不加“独立版”前缀。
- 字号只用 15（数字）、12（说明）、11.5（名称）三档。

涉及的版本行、更新状态、安装提示属于更新功能的页脚，改它们要动 `RemoteBrowserUpdate` 和页脚的样式，实现前需要确认。

## 刷新频率与性能

- 一次采样（CPU 加内存）在这台 Mac 上实测约 12 微秒，每 2 秒一次只占一个核的 0.0006%，可以忽略。
- 网络上每次请求返回一个很小的 JSON（约 200 字节），通过 Relay 时还要加密。
- 多个浏览器同时看这台电脑时共用同一次读取：后端一秒内最多读一次系统。
- 约定：页面在前台且详情展开时每 2 秒一次；只显示收起的卡片时每 5 秒一次；页面切到后台（`visibilitychange`）完全停止；关闭侧栏同样停止。走势只保存在页面里，不落盘。

## 实现约定

- 数据来自新增的 `GET /api/system/stats`，受登录保护，经 Relay 时同样加密。返回 CPU 百分比、核数、内存已用和总量；电脑名字用已有的节点名。
- 后端新增依赖 `github.com/shirou/gopsutil/v4`（BSD-3-Clause）。已在临时项目验证：关闭 CGO 时，macOS、Linux、Windows 的 x64 和 ARM64 六个目标都能编译，macOS 上读到 CPU 与内存。需要把它的许可证文本加入安装包的 `licenses/`。
